## What Aomi does

You send an instruction such as "swap 100 USDC for ETH on Base". Aomi reads the chain, composes the transaction against the protocol's contracts, and simulates it on a fork of live chain state. You see the result: balance changes, approvals, fees and gas. Only then does the request go to a wallet for signature.

Two rules hold everywhere. A transaction that fails simulation never reaches a signer: you fix the request and Aomi builds a new one. And Aomi never holds your keys. The agent proposes, and your wallet, or a signer you have explicitly authorized, signs.

Read [How Aomi works](/concepts/how-aomi-works) for the full pipeline and [Signing and permissions](/concepts/permission-model) for the security model.

## Ways to call Aomi

| Surface | Best for | Auth to start |
| --- | --- | --- |
| [Portal](/guides/portal) | Trading by chat in the browser | Wallet or email sign-in |
| [TypeScript SDK](/quickstart) | Node.js services and browser apps | None (guest mode) |
| [MCP](/guides/mcp) | Coding agents and MCP clients | OAuth in your client |
| [CLI](/guides/cli) | Terminal use, scripts and CI | None (guest mode) |
| [HTTP API](/reference/api) | Any language | Bearer token |

All of them reach the same runtime at `https://chat.aomi.dev`.
