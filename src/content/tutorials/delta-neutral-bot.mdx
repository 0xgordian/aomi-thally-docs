## What the video shows

The speaker's point is that most bot code is connectors, ABI encoding, gas and nonce handling, not the strategy itself. With Aomi, you still write the strategy, then hand execution to Aomi instead of hardcoding router addresses and ABIs. The example instruction in the captions is: swap 10 wrapped SOL for USDC, find the best route, and keep slippage under 1%. The agent searches across DEXes, figures out routing, and sends transaction data back for the bot to sign locally. The key never leaves the program that signed it.

The recorded bot was put together quickly with Claude. The speaker gave Claude a wallet with 100 USDC and 30 wrapped SOL and asked what to build using Aomi for a delta-neutral strategy. In the run that is shown:

- The bot queries SOL price each tick and computes a moving-average spread
- Its logic tries to keep a target allocation from that spread, swapping between SOL and USDC
- It never names the protocol to use. It states the intent plus slippage and allocation constraints
- On one tick it instructed Aomi to sell nine SOL. Aomi chose a Uniswap V3 multi-hop through wrapped ETH and USDC, built a spending approval, and simulated the swap after the approval was signed
- The moving-average metric moved into bearish territory twice, and two trades sold SOL, leaving about 75% USDC and 25% SOL in that run

The captions say simulation happens before the swap is passed back for signature, so a malformed transaction is not signed.

## How to start from the public example

1. Read the official example repo: [github.com/aomi-labs/aomi-client-example](https://github.com/aomi-labs/aomi-client-example).
2. Install the current TypeScript client from the [Client SDK](https://aomi.dev/docs/integrate/client-sdk) guide:

```bash
npm install @aomi-labs/client
export AOMI_BASE_URL="https://chat.aomi.dev"
```

The video mentions a Python program holding the key. I did not open the example repo in this pass, so I cannot say whether today's sample is TypeScript, Python or both. Use the repo README for the language it actually ships.

3. Keep signing local. The client docs cover wallet and signing inside your application. Do not send a private key to the model.
